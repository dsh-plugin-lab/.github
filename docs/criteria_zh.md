# 跨仓判据

[English](criteria.md) | [中文](criteria_zh.md)

**本文写给谁**：你正在判「两仓之间的某处不同」「发出去的某个包」**算不算缺陷** —— 某个 PR 改了版本号、
某次发布读错了东西、两个仓不再长得一样、某个包不再带市场需要的东西。

**本文不自带任何规则。** 下表每一行指向 [plugin-conventions.md](plugin-conventions.md) 里的一条规则，
给它定档，并点名由哪个文件或脚本判它。「这条到底有没有被执行」在这里有答案，不靠感觉。

**本文不写给**：想知道该建什么的人（那是公约）、在某个仓里怎么干活（那个仓的 `AGENTS.md`）、
某次发布怎么跑（那个仓的 `docs/PUBLISHING.md`）。

**不进本文**：论证、权衡与复盘 → [.agents/notes/](../.agents/notes/)。

表里不是每一行都约束本组织的每个仓 —— 插件仓、组织仓、市场各自承担不同的那部分。谁承担哪部分写在
[公约的「本文约束谁」](plugin-conventions.md) 里，不在本文。

三档。表格最后一列不是散文，它点名判这一行的文件或脚本。

| 档 | 含义 |
|---|---|
| **必须一致** | 不一致即缺陷，必须变成一条检查 |
| **应当一致** | 判定逻辑共享，参数各仓自定 |
| **能力可选** | 规则确实不适用 —— **不是**被关掉了 |

| 判据 | 档 | 落点 |
|---|---|---|
| 发出去的包带上公约 §2 的四项输入 | 必须一致 | 各仓 `check:release`（断言 tarball 与清单里有什么）；市场侧的 diagnostics 让遗漏可见 |
| 发出去的包**不带**只给 README 看的图：图住仓里，README 用相对路径 | 必须一致 | 各仓一条红线断言 —— 排除条目在、README 用相对路径、运行期资产仍在包里 |
| 合并的版本真的发到 npm | 必须一致 | 各仓 `docs/PUBLISHING.md` 的发布后核对；全组织范围由市场的漂移报告发现 |
| 声明的每一族宿主都被巡检判过 | 必须一致 | 各仓 `scripts/check-declaration.mjs`，按行打印计数 |
| 锁文件里的 `resolved` 指向官方 registry | 必须一致 | 各仓一条红线断言（条数由脚本数，不写进文档） |
| **只用 pnpm**，`pnpm-lock.yaml` 是唯一锁文件 | 必须一致 | 模板里写明；迁移过的仓其 `.prettierignore` 由 `scaffold check` 对齐 |
| 缺同侪包 → 失败；只缺 dev → 警告并跳过 | 应当一致 | 判定逻辑共享（**默认失败**）；跟哪条宿主线由各仓定 |
| peer 与 dev 的版本必须一致 | 必须一致 | 各仓一条红线断言 |
| 四个编译器开关与 ESLint 各管一层 | 应当一致 | 各仓红线断言「开关存在」；**开关的值住 `tsconfig.json`**，工具参数各仓自定 |
| 发布态不变量 | 必须一致 | 各仓 `check:release`（模板带一份，各仓**只追加**不删）；纯宿主插件可对 `files` 一项豁免，**宿主兼容区间不可豁免** |
| 发布流程**不得**改写版本号 | 必须一致 | `check:release` 里的 `findVersionWrites`，**配反向控制**。改版本号是发布前的独立一步 |
| **手动与 tag 两个入口都能触发**，且 tag 触发时基线排除该 tag | 必须一致 | 各仓发布流程里的一条断言 |
| **正文读 Drafter 草稿**、**发完删草稿**，且**读不到时发 warning** | 必须一致 | 各仓发布流程里的一条断言。没有那条 warning，「发布成功但正文来自回落」就是静默失败 |
| **npm 发布走 OIDC**，全程不传 token | 必须一致 | 各仓发布流程；前置是 npm 后台的 Trusted Publisher（人做，模板带不了） |
| 发版前确认要发的那个提交已在**远端** | 必须一致 | 各仓 `docs/PUBLISHING.md` 的「发布之前」 |
| 一次发布产出的 git 侧产物形状相同（tag 形状、Release 存在、预发布标记） | 必须一致 | 各仓发布流程里的一条断言。tag 名是**机器**在读（守卫用 `git describe --match`），不是纯审美 |
| 宿主兼容声明必须**自洽**，且**整串在跨仓之间可比** | 必须一致 | 自洽由各仓红线断言；整串靠读各自已发布的清单比对。今天是否一致是每次要**重新测**的事实，不是抄进本文的值 |
| 判断依赖归哪一类的判据是「**我们与它的关系**」：只 `import type` → `devDependencies`；**消费它提供的服务** → `peerDependencies` | 必须一致 | 各仓 `AGENTS.md`。判据与现状冲突时，下一个人照判据删 |
| TypeScript 严格开关（`strict` / 索引访问 / 可选属性）的档位 | 应当一致 | **流程**共享：开任何开关前用**真实配置**（不是 CLI 覆盖）数一遍站点，两个一起开必须分开验；**参数按仓**，不做跨仓快照 |
| 兼容巡检里「只记录、不阻断」的项 | 必须一致 | 必须带理由，否则一次绿跑会盖住真问题 |
| 诊断性步骤（例如发布时打印凭据声明） | —— | 属落地实现：**局部于 workflow**，不抽 |
| 路径冲突断言 | —— | **不写**：等价保护已存在，第二份就是重复 |
| CSS 怎么注入、有没有样式表 | 能力可选 | 按仓：规则本身不适用 |
| Drafter 的**分类 → 标签映射** | 应当一致 | 组织仓那份是**默认值**；标签是仓的元数据，按仓设置 |
| 客户端 `inject` 只列真实依赖 | 必须一致 | 用官方自带的校验器，不要写散文 |
| 链接怎么写：**同仓 → 相对路径**；**跨仓（同组织或不同组织）→ 绝对 URL**；一律 `[]()`，不用 `<URL>`，不用裸 URL。作为**值**而不是引用的 URL 放行内代码 | 必须一致 | 各仓 `AGENTS.md`；渲染在组织主页上的文件是例外（那里的链接必须绝对 —— 见那个仓的 `AGENTS.md`） |

**两类内容，分开治理**：

- **断言**（写错 = CI 当场红，**响**）—— 优先。
- **知识**（写错 = 有人读到过期指南，**静**）—— 同一批，但不做成红线。

**一条兜底判据**：当某个仓过不去上游的**类型面**时，它**可以停在还能构建的那条线上** ——
能构建优先于跟线。这不与上面的判据冲突：上面说声明必须与推荐的那条线自洽，这条说自洽的目标可以是更低那条线。
停在不同线上的仓，不必强行对齐。

**为什么判据住在这里而不是某个仓里** → [决策：跨仓判据住组织仓](../.agents/notes/2026-10-12-criteria-live-in-the-org-repo.md)。

## 怎么核对

- **逐字节相同的副本** → 比字节，不比意思。执行体：`node scripts/scaffold.mjs check <repo>...`
  （模板那一份与各仓同名文件做 SHA-256 比对）。不一致**不必然是缺陷** —— 它报的是「知道它不同」，
  不是「强行一样」。哪些文件才是候选，看该脚本里的 `IDENTITY_FILES`。
- **形状** → 读 [plugin-conventions.md](plugin-conventions.md) §1；不要把那里的值抄进仓。
- **一条规矩不能只活在散文里** → 能变成断言的都变成断言（红线测试、`check:*` 脚本）；散文只留指针。
- **对比式描述（「A 有、B 没有」）过期最快** → 它同时依赖两边，照它行动之前先回原始来源核实。
- **管理层设施自己核对**：组织仓没有 CI，靠手工跑（见它的 `AGENTS.md`）；市场有自己的 workflow、测试与
  diagnostics 基线（见它的 `AGENTS.md`）。本文没有任何一行要求这两个仓去满足插件的义务。
