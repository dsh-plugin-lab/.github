# 插件仓通用约定

[English](plugin-conventions.md) | [中文](plugin-conventions_zh.md)

**本文写给谁**：你正在看本组织的某个仓，需要判断某件事**算不算缺陷** —— 某个 PR 改了版本号、
某次发布读错了东西、两个仓不再长得一样。**第 4 节是真正要用的部分**：它很短，而且最后一列
写明每条判据由哪个文件或脚本判，判「这条到底有没有被执行」从此有答案而不是靠感觉。从那里开始。
**本文不写给**：在某个仓里怎么干活（那个仓的 `AGENTS.md`）、怎么贡献（本组织的 `CONTRIBUTING.md`）、
某次发布具体怎么跑（那个仓的 `docs/PUBLISHING.md`）、本组织仓自己怎么维护（它的 `AGENTS.md`）。
**不进本文**：论证、权衡与复盘 → [.agents/notes/](../.agents/notes/)。本文只留判据、每条一行意图、重开条件、核对方法与指针。

判断一个文件该放哪，按顺序问三个问题：

1. **机制支不支持回退？** 支持 → 放组织仓（它的 `.github`），各插件仓代码零改动。
2. **内容通用、但机制不支持？** → 各仓独立，形状写进本文。
3. **内容仓特有？** → 各仓独立，本文不管。

---

## 一、能回退的：放组织仓

GitHub 只在平台支持的位置读这些文件，且**各仓有同名文件时用自己的**。新增仓因此自动继承，且不产生任何提交。

| 文件 | 放哪 | 作用范围 |
|---|---|---|
| `SECURITY.md` | 仓根 | 未自带该文件的仓 |
| `CODE_OF_CONDUCT.md` | 仓根 | 同上 |
| `SUPPORT.md` | 仓根 | 同上 |
| `CONTRIBUTING.md` | 仓根 | 同上 |
| `PULL_REQUEST_TEMPLATE.md` | 仓根 | 同上 |
| `.github/ISSUE_TEMPLATE/*.yml` | **必须在 `.github/ISSUE_TEMPLATE/`** | 同上；某仓一旦自建该目录，本仓模板对它**整体失效** |
| `.github/release-drafter.yml` | 组织仓 | 未自带配置的仓 |
| `profile/README.md` | `profile/` | 组织主页，不属回退机制 |

四条由机制推出的判据：

- **issue 模板必须在 `.github/ISSUE_TEMPLATE/` 下** —— 放仓根不生效，只认那一个路径。症状是「新建 issue 只有空白」，且**不报错**。
- **没有多语言机制** —— `CONTRIBUTING_en.md` 这类名字不被识别；要双语只能写在同一份文件里，不能靠第二份文件。
- **回退只在「本仓没有同名文件」时发生** —— 各仓已有自己的 `CONTRIBUTING.md` 时，组织仓那份永远不会被显示；它服务的是**将来新建的仓**。
- **`SECURITY.md` 写的私密报告入口**是各仓 **Security → Report a vulnerability**，需要各仓单独开启（**私有仓不需要**：仓本身就是私有的）。

## 二、通用但不抽

**`workflow` 类明确不抽**：不做 `workflow_call`，各仓自带一份逐字相同的副本。

- **意图**：否则一处改动会同时改变所有仓 —— 且在各仓的 diff 里看不见 —— 还要多出一层跨仓排障。
- 副本之间靠**逐字相同**约束，不靠模板生成；两个副本不一致时以本文的形状为准。
- **重开条件**：插件仓数量达到 6 个以上，或某个 workflow 开始出现真实的分支逻辑与多仓参数。
- 论证与被否掉的选项 → [决策：workflow 不抽成可调用 workflow](../.agents/notes/2026-10-12-workflow-copies-not-extracted.md)。

**脚手架只播种，不同步**：`scripts/scaffold.mjs` + `templates/plugin/` 只给**新仓**铺一次骨架，
之后**永不回写**任何已存在的仓 —— 所以副本之间照旧靠逐字相同互相约束，与上一条不冲突。
它的 `check` 子命令就是这条判据的执行体；`--verify` 在临时目录里生成一遍、跑生成仓自己的检查，
模板改动以它为准。
论证 → [决策：脚手架只播种、不同步](../.agents/notes/2026-10-12-scaffold-seeds-not-syncs.md)。

**载体状态**：不建共享包、不抽副本。知识类靠指针（宿主官方真源），断言类走各仓各写、接受双向同步。

## 三、各仓自持各件的标准形状

以下只写形状，不含会漂的值（版本号、计数、线名）。

**新建仓不用照抄这里的形状**：脚手架会播种（`node scripts/scaffold.mjs <目录>`，再 `--verify`
跑生成仓自己的检查）。读这一节是为了知道**生成出来那份为什么长这样、哪里允许不一样**，不是来抄的。
**已有仓则拿这一节当对照**：形状是什么、哪几处不让动。

### 3.1 CI 的收口 job

各仓 `ci.yml` 的最后一个 job：让 ruleset 只盯一个状态检查名，内部 job 增删时规则集不用动。

四条不能动：

- **判定只放 step 级** —— 放 job 级时条件为假会让 job 变 `skipped`，而 GitHub 把 `skipped` 当成功。意图：防假绿。
- **`needs` 必须列全本文件的 job id** —— 漏一个，那个 job 红了也照样放行。
- **`if: always()`** —— 否则上游失败会把收口 job 自身也跳过。
- **`skipped` 与 `failure`、`cancelled` 一并判红** —— 没跑过的 job 不能算过。

```yaml
  ci-success:
    name: CI Success
    runs-on: ubuntu-latest
    needs: [<本文件全部 job id>]
    if: always()
    steps:
      - name: Verify all jobs succeeded
        if: contains(needs.*.result, 'failure') || contains(needs.*.result, 'cancelled') || contains(needs.*.result, 'skipped')
        run: |
          echo "::error::有 job 未成功 —— CI Success 判红"
          echo '${{ toJSON(needs) }}'
          exit 1
```

ruleset 的 `required_status_checks` 只配 `CI Success` 这一个名字。

### 3.2 依赖漂移巡检

只开 `github-actions` 生态。意图：本族的 npm 依赖大半在宿主的预发布线上，放开自动 PR 只会变成噪音。

```yaml
version: 2
updates:
  - package-ecosystem: github-actions
    directory: '/'
    schedule:
      interval: weekly
      day: monday
    commit-message:
      prefix: ci
    groups:
      actions:
        patterns: ['*']
```

### 3.3 草稿 Release

**workflow** 各仓一份，逐字相同：

```yaml
name: release-drafter

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: write

jobs:
  update-draft:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: release-drafter/release-drafter@v7
```

- **runner 必须固定 ubuntu**。意图：windows runner 上 action 读不到配置文件，草稿静默为空、**不报错**（action 主版本随官方走）。
- 草稿汇总的是 **PR**，不是 commit：直推 `main` 的提交对它不可见。这是取舍，不是缺陷。

**配置**分两层，落点不同：

- **形状统一**（放组织仓 `.github/release-drafter.yml`，各仓不自带时回退到它）：草稿名、条目行格式
  `- $TITLE (#$NUMBER) @$AUTHOR`、转义集、版本解析。**各仓不重新决定这些。**
- **分类到标签的映射逐仓自定**。标签是**仓库元数据**，本来就不同 —— 实测四仓里 `refactor` 与
  `skip-changelog` 只在**一个**仓存在。组织仓那份是**默认值，不是规范**：标签不一样的仓自带一份
  配置覆盖它。

**`tag-template: 'next'` 不属于可协商的那一层**（它不像分类那样逐仓可定）：发布流程按这个 tag 读草稿。
改它不是改配置，是改所有读它的发布流程。

### 3.4 包管理器与构建

全族只有 **pnpm** 一条路：`pnpm-lock.yaml` 是唯一的锁文件。

- **`pnpm-workspace.yaml` 声明单包工作区**。意图：不声明时 pnpm 把这个目录当非工作区目录，
  依赖树与 CI 装的那棵对不上。
- **安装带 `--config.node-linker=hoisted`**。意图：pnpm 的 symlink linker 在这棵树上解不开浏览器
  半边的同侪包，失败表现为「测试看不见自己的依赖」，而不是一条像样的报错。
- **CI 里 `pnpm/action-setup` 排在 `actions/setup-node` 前面**。意图：反了 `cache: pnpm` 找不到 store。
- **本地钩子走 `pnpm exec`，不走 `npx`**，且带
  `--config.verify-deps-before-run=false`。意图：它要借树里**已有的**工具，一个字节都不下载。
- **构建器是 `tsdown`**，两份配置（宿主半边 ESM、浏览器半边 CJS 信封）在
  `tsdown.config.ts` 里，浏览器半边的 CSS Modules 是那里的一个插件。

### 3.5 TypeScript 与测试骨架

- 宿主半边与浏览器半边各一份 tsconfig；日常与契约**两套** vitest 配置分开。
- 日常配置**显式排除**契约用例；契约配置单跑（不并行、超时放宽）。
- `strict` 必须开。编译器开关负责类型与死代码，ESLint 负责编译器覆盖不到的那一档（格式、hooks、promise、import）——**分工口径跨仓一致，工具参数各仓自定**（分号、引号本就不同）。
- **本地钩子只跑秒级检查**（格式化与 lint 的自动修复），typecheck 与测试留给 CI。意图：钩子一慢，就会有人用 `--no-verify` 绕过，等于没有钩子。
- CI 安装一律走 frozen 模式，不联网解析新版本。
- **每个可维护目录一对双件**：`AGENTS.md` 写「在这里要怎么干」，`README.md` 写「这里有什么、改哪」；同一事实只有一个 home，跨件只给指针。

### 3.6 发布态守卫与兼容巡检

- **发布态不变量**落成 `check:release` 脚本，发布流程在 publish **之前**跑它。脚手架模板带一份，
  新仓出生即满足这条判据；各仓在它后面**追加**自己的断言，不删里面任何一条。
- **发版噪声守卫**（`scripts/release-guard.mjs`）判的是「这段改动能不能改变 npm 上的产物」。
  **排除法**：认不出的路径一律算产物 —— 宁可漏判（多答一次），不误拦。
- **兼容巡检**对着**上游**动没动，本地提交改不了结论，所以按周跑、**不挂 `push`**。
- 换包脚本清残留时**两种锁文件都要清**（`package-lock.json` 与 `pnpm-lock.yaml`）。意图：留着旧锁会让安装直接失败，而**安装失败之后依赖树停在旧版本上、后面每一步都绿**。
- **声明面是若干族的并集**（`||` 分隔）时，测**任何一族**都必须把声明临时收窄到那一族 —— **不只是低族**。意图：不收窄会装出**混合树**，「换到某条线」这一步跑的根本不是那条线。机制 → [依据：并集声明下安装器按 latest 选族](../.agents/notes/2026-10-12-installer-picks-latest-family.md)。
- **收窄会撞上两条读 `package.json` 的红线**：族前缀这类值只写在机器输入行（矩阵值或 `run`），不写进 workflow 注释；跑 typecheck / build / test **之前**把清单还原成提交时的样子。意图：红线判的是**仓库的声明**，不是巡检里临时的收窄形态。论证 → [决策：compat 收窄只服务装与核对，跑测试前还原清单](../.agents/notes/2026-10-12-narrowing-and-redlines.md)。
- **巡检红了的可见性**：定时任务的失败邮件只发给最后改过 cron 的人，不能当主通知 —— 失败要开或更新一条**固定标题**的跟踪 issue（同一处失败不重复刷评论）。

### 3.7 插件图标

包根一份 `icon.svg`，由 `"icon": "./icon.svg"` 声明。

- **画布 36×36**：`viewBox="0 0 36 36"`，`width` / `height` 与它一致。
- **透明底** —— `<svg>` 写 `fill="none"`，且**不要**有任何铺满画布的矩形。宿主把文件画在自己的
  底上，烘进去的背景会显示成一块色板。
- **图形居中**，**紧的那条轴**上留 **7–9**。方形图形四边同距；宽扁或瘦高的图形是「信箱式」居中 ——
  紧的那条轴守住这个边距，另一条轴拿到居中之后的余量。
- **颜色烘死**。不用 `currentColor`、不用主题变量、不用 CSS：宿主按图片渲染，三者都不起作用。
  图形可以用自己的配色。
- **只放图形、渐变与滤镜**。不要脚本，不要外部引用。
- **XML 注释里不许出现连续两个连字符**（`--`）。出现后文件不再被当图片解析，宿主**静默**回落成
  默认图形。
- 支持的格式与体积上限是**宿主**的限制，不是我们的 —— 去宿主的插件参考里查，不要抄在这里。

### 3.8 发布流程

发布层的实现**各仓各写**（模板给一份满足下面四条的参考实现）。四条是行为底线：

| 底线 | 判据 |
|---|---|
| **手动与 tag 两个入口** | tag 触发带一道闸：tag 名必须等于 `v` + 清单版本号 |
| **发版说明读 Drafter 草稿** | 读不到或读空时回落 `--generate-notes`，且**读不到必须发 warning** |
| **发完删掉草稿** | 删的是 tag 不以 `v` 开头的那一个正式版不动 |
| **用 OIDC 发 npm** | 全程不传 token；代价是 npm 后台配一次 Trusted Publisher |

四个容易漏、且漏了都**静默**的点：

- **tag 触发时守卫的基线要排除正在发的那个 tag。** 否则 `describe` 解析出它自己、`<tag>..HEAD`
  恒空，一次完全正常的发布被判成「没有可发布的内容」。
- **「只接受 main」那道判定要带 `github.event_name` 守卫。** 不带的话 tag 触发时 `github.ref` 是
  `refs/tags/...`，每一次 tag 发布都红。
- **建 Release 之前先判存在。** 没有这道幂等，重跑撞 tag 已存在而红。
- **清洗草稿正文要按 action 名匹配那一整行**，不要抄提示语的全文 —— 那句话归组织仓模板所有，
  照抄一句就是一条静默失效的 sed。

**逐仓自己定、不强制的**：发版前的检查链、environment 名字、要不要 GitHub App token 推默认分支、
建 Release 的重试策略。这些的前置配置（labels、environments、secrets、ruleset、npm 后台）
**都不在文件里**，模板替不了，各仓的 `docs/PUBLISHING.md` 写自己那份。

## 四、逐条判据（跨仓一致性）

**这一节才是要动手的地方。** 最后一列不是散文：它点名判这条的文件或脚本，所以「这条到底有没有
被执行」有答案，不靠感觉。第一到三节解释的是下面某行为什么成立，不必按顺序读。

三档的含义：

| 档 | 含义 |
|---|---|
| **必须一致** | 不一致就是缺陷，要落成校验 |
| **最好一致** | 判定逻辑共享，参数各仓定 |
| **能力可选** | 规则本身不适用，**不是被关掉** |

| 规则 | 档 | 落点 |
|---|---|---|
| 锁文件的 `resolved` 必须指向官方源 | 必须一致 | 各仓红线断言（条数现算，不抄进文档） |
| **包管理器只有 pnpm 一条**，`pnpm-lock.yaml` 是唯一锁文件 | 必须一致 | 模板写死；迁移过的仓 `scaffold check` 的 `.prettierignore` 会归位 |
| peer 缺失 → 失败；仅 dev 缺失 → 告警跳过 | 最好一致 | 判定逻辑共享（**默认 fail**），跟哪条宿主线各仓定 |
| peer 与 dev 的版本必须一致 | 必须一致 | 各仓红线断言 |
| 四个编译器开关与 ESLint 各自分工 | 最好一致 | 各仓红线守着开关存在；**开关值留 `tsconfig.json`**，工具参数各仓自定 |
| 发布态不变量 | 必须一致 | 各仓 `check:release`（模板带一份，各仓**追加**不删）；纯宿主插件可豁免 `files` 那条，**宿主兼容范围必须有** |
| 发布流程**不得** bump 版本 | 必须一致 | `check:release` 里的 `findVersionWrites`，**带反向控制**。bump 是发布前的独立一步 |
| **手动与 tag 都能触发**，且 tag 触发时基线排除正在发的那个 tag | 必须一致 | 各仓发布流程断言 |
| **发版说明读 Drafter 草稿**、**发完删草稿**，且**读不到草稿必须发 warning** | 必须一致 | 各仓发布流程断言。少 warning 那条，「发版成功但正文走了回落」就是静默失败 |
| **用 OIDC 发 npm**，全程不传 token | 必须一致 | 各仓发布流程；前置是 npm 后台配 Trusted Publisher（人做，模板替不了） |
| 发布前确认**远端**已有要发的提交 | 必须一致 | 各仓 `docs/PUBLISHING.md` 的「发版前确认」 |
| 发布必须产出**同形**的 git 侧产物（tag 形状、Release 存在、预发布要标出） | 必须一致 | 各仓发布流程断言。tag 名是**机器**在读（守卫靠 `git describe --match`），不是纯审美 |
| 宿主兼容范围与 peer 区间必须**自洽** | 必须一致 | 各仓红线。跨仓只比**下限**（可比），**上界形状各仓自定** |
| 依赖类别的判据是「**我们与它的关系**」：只 `import type` → `devDependencies`；**消费它提供的服务** → `peerDependencies` | 必须一致 | 各仓 `AGENTS.md`。判据与现状对不上时，下一个人会照规则把它删掉 |
| TypeScript 严格开关的档位（`strict` / 索引访问 / 可选属性） | 最好一致 | **流程**共享：开任一开关前用**真实配置**量位点数（不是 CLI 覆盖），两个开关同开必须单独测一次；**参数各仓自定**，不维护跨仓快照 |
| 「只记录不阻断」的巡检项 | 必须一致 | 必须附理由，否则绿会掩盖真问题 |
| 诊断类步骤（例如发布时 dump 凭据声明） | — | 属物化类：**留本地 workflow**，不抽 |
| 路径冲突断言 | — | **不写**：已有等价保护，再写一份是重复 |
| CSS 注入方式、有没有样式文件 | 能力可选 | 留各仓：规则本身不适用 |
| **Drafter 的分类到标签映射** | 最好一致 | 组织仓那份是**默认值**；标签是仓库元数据，逐仓自定（实测四仓里 `refactor` 与 `skip-changelog` 只在一个仓存在） |
| 客户端 `inject` 只列真实依赖 | 必须一致 | 用官方自带校验器，不另写散文 |
| 文档里的链接写法：**同仓 → 相对路径**；**跨仓（同组织或外部）→ 绝对 URL**；一律 `[]()`，不用 `<URL>`、不用裸 URL。URL 作为**值**而非引用时用内联代码 | 必须一致 | 各仓 `AGENTS.md`；渲染在组织主页上的文件是例外（那里的链接必须绝对 URL，见组织仓 `AGENTS.md`） |

**两类内容分开治理**：

- **断言**（错了 = CI 当场红，**响**）—— 先上。
- **知识**（错了 = 有人读了过期指南，**安静**）—— 同批做，但不算红线。

**一条兜底判据**：某个仓撞上上游**类型面**过不去时，**有权停在能构建的那条线上** ——
能构建优先于跟线。这条与上面各条不冲突：上面说的是「声明要与被推荐的线自洽」，
这里说的是「自洽的对象可以是更靠下的那条线」。各仓停在线上不必强行对齐。

**这些判据为什么住在这里、不住在某个仓里** → [决策：跨仓判据住在组织仓，各仓只留指针](../.agents/notes/2026-10-12-criteria-live-in-the-org-repo.md)。

## 五、怎么核对

- **逐字相同的副本** → 比字节，不比语义。执行体：`node scripts/scaffold.mjs check <仓>...`
  （模板里那一份与仓内同名文件做 SHA-256 比对）。不一致**不必然是缺陷** ——
  它报的是「知道它不同」，不是「强行一样」。
- **形状** → 照本文的判据看，不照本文抄值。
- **规则不能只写在散文里** → 能落成断言的就落成断言（红线测试、`check:*` 脚本），散文只留指针。
- **对比型描述（「A 有、B 没有」）最易陈腐** → 它同时依赖两边状态，动手前回原始来源现查一次。
